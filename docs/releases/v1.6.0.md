# VoicePrompt 1.6.0 - Durable mobile streaming

This release updates Android to **1.3.0** (version code 4) and the mobile cloud
pipeline. The Windows download remains the unchanged **1.5.1** installer.

## Android

- New recordings default to **continuous cloud streaming**, automatic language
  detection and optional LLM polishing **off**.
- Capture produces contiguous **ten-second PCM16/16 kHz mono WAV segments**, without
  overlap. Exact source sample positions/counts are included with each upload.
- Recording remains independent of a live phone socket. The existing durable
  WorkManager create/upload/complete chain keeps network retries and ack-then-delete.
- The foreground screen shows provisional cloud text and recovery status. Preview
  text is never delivered incrementally to the Windows clipboard.
- Settings can enable optional final polishing or restore legacy chunked
  transcription for new recordings.
- A non-destructive Room migration preserves pending recordings, chunk rows and
  audio-file references. Existing recordings keep their original processing choices.
- Capture persistence is bounded; incomplete PCM and overload fail explicitly
  instead of silently dropping source samples.

## Cloud worker and recovery

- One leased worker sends the safely uploaded contiguous prefix to **one
  MAI-Transcribe-2-Streaming session**, not one independent STT call per file.
- WAV headers are removed. File boundaries do not commit/reset the model, and
  waiting for uploads does not insert PCM silence or skip missing ranges.
- Available audio is paced at up to **4x real time** by default. Queue receipts and
  recording leases renew during processing; scaling counts invisible leased work.
- Cloud audio survives failed sessions. Recovery discards provisional text and
  replays from sample zero; expired owners cannot publish a canonical result.
- A final commit happens only after all declared segments have arrived. Finalization
  uses the canonical full transcript directly, with no independent-STT stitching.
- Optional polishing runs only when that recording enabled it. Unpolished transcript
  metadata uses `refine_model=none`.
- Streaming audio is content-addressed, so competing uploads cannot overwrite the
  accepted bytes. Identical upload retries repair failed queue wakeups.
- Completed-text notification retry preserves the same transcript and event ID.
  Windows deduplicates at-least-once notifications.
- Audio is removed after final transcript completion. Failed streaming audio and
  unpublished attempt results remain bounded by retention cleanup. Final text expires
  **48 hours after completion**.
- Older Android clients and existing legacy recordings continue to use their
  independent chunk pipeline. Windows live dictation and its cloud audit are unchanged.

## Downloads and upgrade

- **VoicePrompt-Android.apk:** signed Android **1.3.0**, Android 10 or newer. The
  signing certificate matches previous releases; install as an update, **do not
  uninstall the existing app**. USB debugging is not required for manual APK installation.
- **VoicePrompt-Setup.exe:** unchanged public Windows x64 **1.5.1** installer from
  v1.5.1, requiring .NET 8 Desktop Runtime. Existing Windows 1.5.1 users do not need
  to reinstall. It remains unsigned and excludes local OAuth configuration.
- **SHA256SUMS.txt:** SHA-256 checksums for both downloads.

Deploy the updated **worker, API and cleanup job before the APK**. The managed
identity must have access to the configured Foundry streaming deployment. The hosted
backend has already been updated; private Storage, Google account allowlisting and
the restored ReadOnly resource-group lock remain in place.

No Microsoft login or model key is added to Android. New Windows installations
still need [Desktop OAuth setup](../google-oauth.md).

## Evidence and limits

- Local checks passed **475 backend tests**, strict Python types, lint/format,
  **158 Android JVM tests** and the signed release build. Azure emulator and
  opt-in refinement tests were not part of that backend pass.
- Byte-level regressions cover contiguous PCM, exact overlap removal, gaps, full
  replay, lease ownership, queue receipt renewal, publication and notification faults.
  Android tests cover contiguous capture and preservation of pending Room data.
- The actual worker processed a **30-minute synthetic cold backlog** through real
  MAI with fake Storage in **461.34 seconds**, about 3.90x real time. Audio remained
  until finalization; there were no LLM calls and one completed notification.
  The source repeated a short fictional clip, not diverse natural speech.
- Hosted checks exercised real private Storage/Queue/Table, managed identity, MAI,
  duplicate/out-of-order uploads, provisional preview and exact Windows clipboard
  delivery. A 49.55-second fixture released at ten-second capture boundaries was
  fetched as final text **6.92 seconds after EOF was declared**, including HTTP,
  finalization and two-second status polling. This is one synthetic run, not a
  latency guarantee.
- Real microphone quality, locked-screen capture, radio changes and battery behavior
  for Android 1.3.0 still require physical-device checks.

MAI remains public preview without SLA. Streaming removes seams caused by independent
STT windows, not ordinary recognition errors or intentional repetitions. A hard process
crash can still lose an incomplete window and queued, not-yet-persisted audio. Device
or disk loss is not recoverable. Long offline backlogs require replay time; the fast
Windows Stop path does not imply instant cold transcription of a long mobile recording.
