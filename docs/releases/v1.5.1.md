# VoicePrompt 1.5.1 - Live streaming dictation

This release combines the Windows 1.5 streaming upgrade and the 1.5.1 overlay fix.
Android recording and its asynchronous cloud pipeline are unchanged.

## Windows

- Live dictation uses **MAI-Transcribe-2-Streaming** through a thin backend WebSocket
  relay. The existing Google sign-in is sufficient; no Microsoft login or Azure
  model key is installed on the desktop.
- The overlay displays changing provisional hypotheses while speaking. Only
  confirmed text can be delivered. After successful paste the overlay hides
  immediately, replacing the previous 900 ms "Pasted" status. Skipped-paste status
  and actionable clipboard/history notifications remain.
- Capture is independent of the connection. DPAPI-encrypted audio checkpoints are
  saved about every two seconds; reconnect replays after the last durable confirmed
  byte cursor. Old recovery journals remain readable.
- If the complete transcript is not ready within the streaming stop-time budget,
  nothing incomplete is pasted. **Recovery** can finish remaining audio through the
  existing MAI WAV endpoint into History, without automatic paste.
- **Use live MAI streaming** defaults on. Uncheck it in Settings to restore the
  legacy short-WAV path. Existing shortcuts, Google configuration, local history
  and optional LLM-polishing preferences are preserved.
- Optional LLM polishing remains optional and bounded. The streaming overlay
  continues to show live ASR hypotheses rather than an older polishing window.
- Cancellation also guards requests that acquire a legacy transcription slot while
  cancellation callbacks are releasing earlier slots; queued work cannot start
  transcription after Cancel.

## Cloud audit and backend

- Completed streaming dictations, including recovered recordings, archive original
  and final text for **48 hours from completion**. An encrypted durable desktop
  outbox retries uploads independently of paste and survives restart.
- Audit publication is idempotent. Identical retries cannot extend retention;
  conflicting text for the same recording UUID cannot overwrite the original.
- Audit entries are retrievable through cloud History and emit no mobile-style
  completion event, so they cannot unexpectedly overwrite the clipboard.
- Provisional or explicitly discarded dictations are not archived. The live relay
  itself stores no audio and uses no queue, worker, LLM or storage request.
- Deploy the updated **API and cleanup job** before enabling streaming. Configure
  an existing Foundry `MAI-Transcribe-2-Streaming` deployment accessible to the API's
  managed identity. The Android worker does not need this desktop-only upgrade.
- Container builds use the approved package feed for both pip and uv. Dependency
  versions remain unchanged; websockets is now an explicit runtime dependency.

## Downloads and upgrade

- **VoicePrompt-Setup.exe:** unsigned Windows x64 **1.5.1** installer, requiring
  .NET 8 Desktop Runtime. It excludes local OAuth configuration and preserves
  existing settings, sign-in data and history.
- **VoicePrompt-Android.apk:** unchanged signed Android **1.2.1** package from
  release v1.4.5. No Android upgrade is required for these Windows improvements.
- **SHA256SUMS.txt:** SHA-256 checksums for both artifacts.

New Windows installations must configure Desktop Google OAuth. Existing configured
installations retain their configuration. The hosted backend remains restricted to
its configured account allowlist.

## Validation and limits

Local validation covered the backend unit/API contract suite, strict Python types,
the Windows core suite, and native hotkey/overlay/controller probes. New regressions
cover provisional-suffix replacement, interrupted-stream replay, retained offline
audio, atomic confirmation, audit retry/account binding, expiry and publication
failures, immediate overlay hiding and retained skipped-paste feedback.

A paced **23.525-second synthetic Czech WAV**, sent by the actual Windows streaming
engine through the hosted Google-authenticated relay, completed **456 ms after Stop**.
Original and final text were then archived and retrieved with exact equality and
48-hour expiry. This excluded microphone capture, optional LLM polishing and real
clipboard/paste delivery; it is a single healthy-path measurement, not p95 or a
latency guarantee. Native paste safeguards were validated separately with controlled
transcription and clipboard/desktop fakes. No private recording was uploaded by
these release checks.

MAI streaming remains **public preview without SLA**. An outage near Stop can require
later recovery; the stop-time budget never justifies pasting an incomplete result.
Capture checkpoints are not a lossless audio archive: a crash can lose audio since
the last checkpoint plus queued microphone buffers, and disk/user-key loss is not
recoverable. Cloud audit is an application transcript archive, not an independently
attested compliance log.
